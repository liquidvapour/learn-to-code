# Working in this repository

- Make small, focused changes. Each change should add one real, reviewable piece of behaviour or design.
- Do not create commits. Stop each coherent step at the commit boundary, leaving its changes staged for the user to commit.
- Keep each step as small as possible while still leaving the project in a useful, working state.
- End each step with a clear suggested commit message that describes what it adds or fixes.
- Run checks appropriate to the change before staging code. If a check cannot run, say so.
- Do not stage unrelated edits. Preserve existing work and inspect the Git diff before staging.
- When a task needs several steps, complete one reviewable step at a time and stop for the user to commit before continuing.
- Keep `plan.md` current as steps are completed. Break down upcoming work before implementing it, and leave distant work broad.
